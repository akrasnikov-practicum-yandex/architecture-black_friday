# Архитектура и Базы Данных: Black Friday

Этот репозиторий содержит финальный проект, посвященный проектированию масштабируемой и отказоустойчивой инфраструктуры данных на базе **MongoDB**, **Redis**, а также архитектурному планированию **API Gateway**, **Service Discovery (Consul)** и **CDN**.

## Выполненные задачи и структура репозитория

1. **Архитектурные схемы:** `diagrams/task1.drawio`
   Включает 5 вложенных диаграмм с пошаговым развитием архитектуры (от простой БД до масштабируемой системы с шардированием, кэшем, Consul и сетью доставки статики CDN).
2. **Базовое шардирование:** `mongo-sharding/`
   MongoDB-кластер с роутером и шардированием (без отказоустойчивости узлов).
3. **Шардирование + Репликация:** `mongo-sharding-repl/`
   Развертывание отказоустойчивых Replica Sets (по 3 узла) для конфигурационных серверов и каждого шарда.
4. **Кэширование + Полная инфраструктура:** `sharding-repl-cache/`
   **Финальный стенд для проверки**. Включает предыдущие наработки + слой кэширования на базе Redis + веб-админку Mongo-Express.

##  Как запустить финальный стенд 

Для проверки проектной работы мы будем использовать директорию `sharding-repl-cache`.

### Шаг 1. Запуск инфраструктуры
Перейдите в директорию финального задания и запустите контейнеры:
```bash
cd sharding-repl-cache
docker compose up -d
```
Убедитесь, что все 13 контейнеров (включая API, Redis, Mongo-узлы и Mongo-Express) работают:
```bash
docker compose ps
```

### Шаг 2. Автоматическая инициализация кластера (Скрипт)
Кластер требует настройки: создания Replica Sets, привязки шардов к роутеру `mongos` и генерации тестовых данных.
Для автоматизации этого процесса из папки `sharding-repl-cache` вызовите скрипт инициализации:

* **Для Linux / macOS:**
  ```bash
  bash ./init-sharding-repl.sh
  ```
* **Для Windows:**
  ```bash
  wsl ./init-sharding-repl.sh
  ```
*(Скрипт содержит встроенные таймеры с ожиданием ответа баз, поэтому процесс инициализации займет ~30-40 секунд)*.

### Шаг 3. Проверка работы API и Redis
Откройте в браузере или выполните GET-запрос:
**`http://localhost:8080/helloDoc/users`**

1. Первый запрос займет чуть больше секунды, так как приложение сымитирует долгий поиск в БД.
2. Сделайте **ВТОРОЙ** запрос (Ctrl+R / F5). Благодаря интегрированному слою **Redis** данные будут отданы из кеша мгновенно (в пределах пары миллисекунд), минуя чтение с серверов MongoDB!

Вы также можете проверить корень **`http://localhost:8080/`**, чтобы получить от API полный системный слепок: подтверждение работы кеша (`cache_enabled: true`) и топологию MongoDB (`mongo_topology_type: "Sharded"`).

### Шаг 4. Визуализация в Mongo-Express
Получите быстрый визуальный доступ к данным кластера, открыв веб-админку, привязанную к порту роутера `mongos`:

🔗 **`http://localhost:8081/`**
* **Логин:** `admin`
* **Пароль:** `pass`

В админке вы найдете базу `somedb` и зашардированную коллекцию `helloDoc`. В ней лежат 1000 пользовательских записей, которые были равномерно распределены по двум отказоустойчивым Replica-шардам.
